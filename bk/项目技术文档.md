## 一、项目概述

### 1.1 背景与痛点

「系统架构设计师」是软考高级资格中含金量最高的科目之一，其备考过程面临以下痛点：

| 痛点 | 具体表现 |
|------|----------|
| **素材分散** | 教材、讲义、真题、补充资料分布在 PDF、Word、Excel 多种格式中，人工整理耗时巨大 |
| **格式混乱** | 大量培训资料带有水印、页眉页脚广告，干扰阅读 |
| **缺乏结构化** | 知识点之间关联性弱，难以形成体系化记忆 |
| **输出单一** | 传统方式只能产出静态文档，无法自动生成思维导图、统计图表等多模态学习资料 |
| **个性化不足** | 不同考生基础不同，但市面上的资料"一刀切"，难以按需调整深度和侧重点 |

### 1.2 项目定位

本项目是一个面向「软考系统架构设计师」备考场景的 **AI 辅助学习资料自动生成工作台**。它将散落在各类文档中的原始素材，通过 OCR → 清洗 → AI 深度加工 → 多格式导出的全链路流水线，实现**一站式、可定制、多模态**的学习资料生产。

### 1.3 目标用户

- **备考考生**：快速将教材转化为结构化学习资料、思维导图、速记卡片
- **培训讲师**：批量生成标准化讲义，并针对不同班级调整深度和案例
- **知识整理者**：将零散技术文档沉淀为可复用的知识体系

### 1.4 核心价值

```
输入：散乱的 PDF课件 + Word讲义 + Excel数据表
            ↓
        [OCR + 清洗 + AI 加工]
            ↓
输出：结构化 Markdown 学习资料
       ├── 精美排版 Word 文档
       ├── Mermaid / Markmap / XMind 思维导图
       ├── 自动统计图表（柱状/饼图/雷达/散点）
       └── 冲刺速记版 / 完整版 双版本
```

### 2.1 技术栈总览

| 层级 | 技术/框架 | 用途 |
|------|----------|------|

## 三、核心模块详解

### 3.1 `modules/config_manager.py` — 全局配置中心

**职责**：统一管理环境变量、章节顺序、水印规则、API 参数。

**关键设计**：
- 使用 `dataclass` 定义 `AppConfig`，类型安全且可序列化
- 自动根据 `base_url` 推断模型厂商（DeepSeek / Moonshot / OpenAI）
- 支持多 Key 兼容：优先读取 `DEEPSEEK_API_KEY`，其次 `MOONSHOT_API_KEY`
- 硬编码 22 章知识体系顺序，从「计算机硬件」到「论文写作专题」

```python
@dataclass
class AppConfig:
    api_key: str
    base_url: str
    model: str
    max_tokens: int = 8192
    temperature: float = 0.7
    # 水印正则规则列表（12 条）
    watermark_patterns: List[str] = field(default_factory=list)
    # 章节顺序映射
    chapter_order: Dict[str, int] = field(default_factory=dict)
```

### 3.2 `modules/ocr_engine.py` — PDF OCR 引擎

**职责**：将扫描版/图片版 PDF 转换为 Markdown 文本。

**关键设计**：
- **延迟导入**：`rapidocr`、`fitz`（PyMuPDF）、`cv2` 均在函数内部导入，避免启动时加载重型库
- **逐页进度回调**：通过 `progress_callback(page_num, total_pages)` 支持前端进度条
- **DPI 可调**：根据 PDF 清晰度动态调整分辨率，平衡速度与准确率
- **批量处理**：`batch_process()` 接口支持整个 `input/` 目录的自动化转换

### 3.3 `modules/local_processor.py` — 零成本本地清洗器

**职责**：在不调用任何 API 的情况下，将原始 Markdown 清洗为结构化学习资料。

**处理流程**：
1. **去水印**：利用 12 条正则规则，过滤「文老师软考教育」「淘宝搜索」等培训广告
2. **结构化提取**：按 Markdown 标题层级识别「考情分析」「各小节知识点」「真题演练」三大区块
3. **自动排序**：根据 `config_manager` 中的章节顺序重新排列文件
4. **目录生成**：自动插入章节目录与页内锚点
5. **冲刺速记占位**：为每章预留「速记卡片」占位符，供考生手动填充

**适用场景**：无网络环境、无 API 余额、仅需快速去杂质的场景。

### 3.4 `modules/ai_generator.py` — AI 生成引擎

**职责**：统一封装 LLM 调用，提供学习资料生成、思维导图生成两大能力。

**核心函数**：

| 函数 | 模式 | 说明 |
|------|------|------|
| `call_llm()` | 流式/非流式 | 底层通用调用，通过 `stream_callback` 解耦前端展示 |
| `generate_study_guide()` | 完整模式 | 将全部素材一次性发送给 LLM，适合短素材 |
| `generate_study_guide_batch()` | 逐章模式 | 每章分别调用 API 后合并，避免长文本超时 |
| `generate_mindmap()` | 一次性 | 基于全部素材生成 Markmap + Mermaid 双格式 |

**双生成模式的设计考量**：
- **完整模式**：上下文连贯，AI 能跨章节建立关联，适合 50 页以内的素材
- **逐章模式**：规避 API 的 max_tokens 限制和超时风险，适合 200+ 页的全套教材

### 3.5 `modules/prompt_manager.py` — 提示词管理器

**职责**：Jinja2 模板渲染与默认提示词兜底。

**关键设计**：
- **模板文件驱动**：`prompts/study_guide.j2`、`prompts/mindmap.j2` 可由用户自定义
- **无模板降级**：若 Jinja2 未安装或模板文件缺失，自动回退到内置默认提示词
- **System + User 双消息模式**：
  - System Prompt：由模板渲染，包含角色定义、素材内容、输出要求
  - User Prompt：简化的触发指令（"请根据以上要求生成..."）

### 3.6 `modules/docx_converter.py` — Markdown → 精美 Word

**职责**：将 AI 生成的 Markdown 转换为排版专业的 Word 文档。

**排版规格**：
- **字体**：微软雅黑（正文 10.5pt / 标题逐级放大）
- **配色**：蓝灰学术色系（主色 `#1a3c6e`、辅色 `#2c5f8a`）
- **表格**：表头深蓝底白字 + 斑马纹行交替
- **页面**：A4 纸张，上下边距 2.54cm，左右边距 3.17cm
- **图片嵌入**：自动识别 Markdown 图片链接，下载并嵌入文档

### 3.7 `modules/mindmap_renderer.py` — 思维导图渲染器

**职责**：将 Mermaid 思维导图代码转换为可视化的 PNG/SVG。

**双后端策略**：
- **mermaid-cli (mmdc)**：优先使用，通过子进程调用 Node.js 渲染，质量高
- **Playwright**：降级方案，纯 Python 驱动 Chromium 渲染，无需额外安装 mmdc

### 3.8 `modules/excel_charter.py` — 智能图表生成器

**职责**：从 Markdown 表格或 Excel 文件中提取数值数据，自动生成统计图表。

**双模式决策**：
1. **自动规则模式**：根据行列数和数据分布自动判断图表类型
   - 类别 + 单一数值列 → 柱状图
   - 时间序列 → 折线图
   - 占比数据 → 饼图
   - 多维度评分 → 雷达图
2. **LLM 智能模式**：将数据发送给 LLM，由 AI 根据数据语义选择最合适的图表类型和配色

### 3.9 `modules/xmind_exporter.py` — XMind 导出器

**职责**：将 Mermaid 思维导图代码转换为 `.xmind` 文件。

**关键设计**：
- **零第三方依赖**：仅使用 Python 标准库 `zipfile` + `xml.etree`
- **多层嵌套解析**：支持无限层级的话题嵌套
- **兼容 XMind 8 / 2024**：生成标准格式的 ZIP + XML 结构

## 四、数据处理流程

### 4.1 完整工作流（一键全链路）

```
input/ (PDF课件/Word讲义/Excel数据)
    │
    ▼ 上传 / 批量转换
output_md/ (每章一个 .md 文件，已 OCR/提取)
    │
    ├──→ [本地模式] ─────────────────────────┐
    │      local_processor.py 清洗重组       │
    │      → 综合学习资料_自动生成.md         │
    │                                        │
    └──→ [API 模式] ─────────────────────────┤
           ai_generator.py                  │
           ├─ 完整模式：全部素材一次性发送     │
           └─ 逐章模式：每章分别调用 API 合并  │
           → 综合学习资料_AI生成.md           │
                                           │
    ┌──────────────────────────────────────┘
    ▼
modules/excel_charter.py
    ├─ 解析 Markdown 表格中的数值数据
    ├─ 自动规则 / LLM 智能决策图表类型
    └─ charts/ 输出 PNG 统计图表
    ▼
modules/docx_converter.py
    ├─ Markdown → 精美 Word（标题/表格/行内格式）
    └─ embed_images_to_docx() 嵌入统计图表
    ▼
modules/ai_generator.py (generate_mindmap)
    ├─ 生成 Markmap 格式 + Mermaid mindmap 代码
    ▼
modules/mindmap_renderer.py
    ├─ Mermaid → PNG 图片
    ▼
modules/xmind_exporter.py
    └─ Mermaid → .xmind 文件
```

### 4.2 本地模式 vs API 模式对比

| 维度 | 本地模式 | API 模式 |
|------|----------|----------|
| **成本** | 零 API 费用 | 按 Token 计费 |
| **网络依赖** | 无需联网 | 需要联网 |
| **生成质量** | 清洗重组，无 AI 润色 | 深度加工，语言精炼 |
| **速度** | 秒级完成 | 取决于素材长度（1~10 分钟） |
| **适用场景** | 快速去杂质、无网络环境 | 最终版学习资料、思维导图 |
| **输出模块** | 基础结构化 + 目录 | 考情分析 + 考点精讲 + 口诀 + 真题 |

## 五、前端界面

### 5.1 Streamlit 版 (`app.py`)

**定位**：快速原型与内部工具，适合个人开发者快速上手。

**核心特性**：
- **宽屏布局**：`layout="wide"`，左侧边栏配置 + 右侧主内容区
- **自定义 CSS**：注入 300+ 行样式，实现卡片容器、暗黑模式、按钮动效
- **卡片式章节选择器**：3 列网格布局，点击切换选中状态
- **提示词工作台**：支持编辑/预览/重置/AI 辅助修改/基于知识库生成模板
- **知识库浏览器**：左侧文件列表 + 右侧编辑/渲染预览双栏
- **流式输出**：打字机效果实时展示 AI 生成内容
- **Pipeline 仪表盘**：可视化展示当前处理阶段与进度

### 5.2 Flask HTML 版 (`backend/app.py` + `static/`)

**定位**：生产级 Web 应用，适合培训场景部署给学员使用。

**文件结构**：
```
backend/
├── app.py          — Flask 服务器（1108 行），REST API + SSE 流式
└── static/
    ├── index.html  — 单页应用（464 行），6 个标签页
    ├── css/style.css — 设计系统（958 行），CSS 变量主题 + 玻璃态 + 暗黑模式
    └── js/app.js   — 前端逻辑（1148 行），API 封装 + SSE + Toast 通知
```

**核心特性**：
- **响应式侧边栏**：桌面端固定左侧，移动端滑出遮罩层
- **实时状态指示器**：就绪/运行中/完成三种状态色标
- **SSE 流式输出**：Server-Sent Events 将 AI 流式响应推送到日志区域
- **与 Streamlit 功能对等**：素材管理、执行生成、结果下载、提示词工作台、知识库浏览器、图表分析 6 大模块全覆盖

## 六、Prompt 设计与 AI 交互

### 6.1 模板系统

| 文件 | 用途 | 模板变量 |
|------|------|----------|
| `prompts/study_guide.j2` | 学习资料生成 | `{{ material }}`, `{{ focus_areas }}`, `{{ detail_level }}`, `{{ include_mnemonics }}`, `{{ include_exercises }}` |
| `prompts/mindmap.j2` | 思维导图生成 | `{{ material }}`, `{{ format_pref }}` |

### 6.2 输出结构规范

AI 生成的学习资料必须包含 6 大固定模块：

1. **📊 考情分析**：该章节在历年考试中的分值占比、题型分布、高频考点
2. **📝 知识点体系**：树状层级结构，从章到节到点的完整知识地图
3. **🎯 考点精讲**：每个核心考点的深入解析，配合示例代码或架构图描述
4. **⚠️ 新教材变化**：第二版教材相较第一版的增删改内容
5. **📌 记忆口诀/技巧**：为抽象概念设计助记符、类比、口诀
6. **✅ 真题演练**：历年真题精选 + 详细解析

### 6.3 思维导图双格式输出

- **Markmap**：基于 Markdown 标题层级的思维导图，可在 VS Code 插件中交互式浏览
- **Mermaid**：标准 Mermaid `mindmap` 语法，支持 GitHub/Notion/VS Code 原生渲染

## 七、配置与部署

### 7.1 环境配置

复制 `.env.example` 为 `.env`，填写以下变量：

```bash
# DeepSeek（默认）
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx

# 或 Moonshot(Kimi)
MOONSHOT_API_KEY=sk-xxxxxxxxxxxxxxxx

# 通用覆盖
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

### 7.2 启动方式

| 方式 | 命令 | 访问地址 |
|------|------|----------|
| Streamlit 主界面 | `streamlit run app.py` | http://localhost:8501 |
| Flask 后端 + HTML 前端 | `python backend/app.py` | http://localhost:5001 |
| CLI 生成学习资料 | `python generate_with_deepseek.py [--batch/--chapter N]` | — |
| CLI 生成思维导图 | `python generate_mindmap.py [--batch/--chapter N]` | — |
| CLI 转换 Word | `python convert_to_docx.py --input xxx.md` | — |

### 7.3 目录约定

```
input/          — 原始素材（PDF/Word/Excel）
output_md/      — OCR/提取后的 Markdown 知识库
output_mindmap/ — 思维导图输出（Mermaid / Markmap / XMind）
temp_output/    — 临时生成文件（含带封面的 PDF）
charts/         — 统计图表输出（PNG）
prompts/        — Jinja2 提示词模板
modules/        — 核心 Python 模块包
backend/        — Flask 后端与静态资源
```

## 八、关键设计决策

### 8.1 双前端策略

**决策**：同时维护 Streamlit 和 Flask/HTML 两套前端。

**理由**：
- Streamlit 适合快速迭代和内部演示，Python 纯代码描述 UI，无需写前端三件套
- Flask/HTML 适合对外发布，完全可控的 CSS/JS，响应式布局和动画效果更精致
- 两套前端共用同一套 `modules/` 业务逻辑，零重复代码

### 8.2 延迟导入依赖

**决策**：`ocr_engine.py` 及各重型库均采用函数内导入。

**理由**：
- 避免启动时因缺少某个库（如 `rapidocr`）而导致整个系统崩溃
- 用户如果只需要 Word 转换功能，无需安装 OCR 相关的重型依赖
- 符合「按需加载」原则，降低环境配置门槛

### 8.3 模板兜底机制

**决策**：Jinja2 模板缺失时自动降级为内置默认提示词。

**理由**：
- 确保系统在任何情况下都能运行，不因文件缺失而崩溃
- 降低首次部署的复杂度，用户无需手动创建模板文件
- 内置提示词经过调优，可作为自定义模板的参考基准

### 8.4 流式与非流式统一封装

**决策**：`call_llm()` 单函数处理两种模式，通过 `stream_callback` 解耦。

**理由**：
- 前端无论是否需要实时展示，都调用同一接口
- 非流式模式下 `stream_callback` 为 `None`，内部自动走同步分支
- 流式模式下回调函数逐段接收文本，前端可实时渲染打字机效果

### 8.5 水印规则硬编码 vs 配置化

**决策**：水印正则规则写在 `config_manager.py` 的 dataclass 默认值中。

**理由**：
- 软考培训资料的水印高度同质化（文老师、淘宝搜索等），规则稳定
- 如果需要新增规则，用户可通过修改源码或后续扩展的配置文件覆盖
- 避免在 `.env` 中写复杂的多行正则，降低配置错误率

## 十、总结

本项目是一个**功能完整、架构清晰、工程化程度较高**的 AI 辅助学习资料生成工具。它在每个环节都做了扎实的设计：

- **输入层**：支持 PDF（OCR）、Word（含 .doc 兼容）、Excel 三种格式
- **处理层**：本地清洗与 AI 深度加工双模式可选，灵活应对不同场景
- **输出层**：Markdown / Word / 思维导图（4 种格式）/ 统计图表 / XMind 全覆盖
- **交互层**：Streamlit 快速上手 + Flask/HTML 精致体验，满足不同用户群体

改进方案中规划的 Pipeline 引擎和可插拔模块系统，显示项目有明确的向 **"可配置、可扩展的 AI 内容生成平台"** 演进的意图，具备良好的长期维护价值和商业转化潜力。
