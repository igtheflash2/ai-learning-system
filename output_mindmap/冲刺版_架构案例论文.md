## 架构风格（选择+案例必考）

### 数据流风格
#### 批处理
- 传统批量计算模型
- 每个阶段独立处理
- 典型：编译器 Lex/Yacc
#### 管道-过滤器
- 过滤器处理数据流
- 管道连接过滤器
- 优点：可复用/可组合/易于理解
- 缺点：不适合交互式应用

### 调用/返回风格
#### 主程序-子程序
- 单线程控制
- 子程序调用返回
#### 面向对象
- 数据+操作封装
- 消息传递
#### 分层
- N 层模式
- 上层依赖下层
- 典型：OSI/TCP/IP 协议栈
- 优点：解耦/可替换/易于维护
- 缺点：性能开销/级联修改

### 独立构件风格
#### 进程通信
- 同步/异步消息
- 共享内存
#### 事件驱动（隐式调用）
- 事件发布→订阅
- 松耦合
- 典型：GUI 框架/消息队列

### 虚拟机风格
#### 解释器
- 执行虚拟指令
- 典型：JVM / Python 解释器
#### 规则系统
- IF-THEN 规则匹配
- 专家系统

### 仓库风格
#### 数据库系统
- 共享数据存储
- 多应用访问
#### 黑板系统
- 中心黑板存储
- 多知识源协作
- 典型：语音识别

## 质量属性（论文+案例必考）

### 六个核心属性
#### 可用性 Availability
- 故障检测/恢复/隔离
- 冗余/心跳/集群
#### 性能 Performance
- 响应时间/吞吐量/资源利用率
- 缓存/池化/异步/负载均衡
#### 安全性 Security
- 认证/授权/加密/审计
- 防御纵深/最小权限
#### 可修改性 Modifiability
- 模块化/接口稳定/低耦合
- 策略：依赖注入/配置化/插件
#### 可测试性 Testability
- 接口驱动/ Mock/ 日志
#### 易用性 Usability
- 用户模型/反馈/防错

### 场景描述六要素
- 刺激源 / 刺激 / 环境 / 制品 / 响应 / 响应度量

### 质量属性效用树
- 分类 → 优先级划分 → 场景细化

## 架构设计方法

### ABSD（基于架构的软件设计）
- 架构驱动 + 质量优先
- 迭代过程：架构定义 → 文档化 → 评估 → 实现 → 演化

### DSSA（领域特定架构）
- 三要素：领域模型/参考需求/参考架构
- 三阶段：领域分析→设计→实现

## 案例专题：解题思路

### 步骤一：读题标记
- 标记系统规模/约束/功能/质量属性关键词

### 步骤二：确定架构风格
- 根据需求匹配适当风格
- 列出优点和潜在问题

### 步骤三：质量属性分析
- 识别关键质量属性
- 设计相应策略

### 步骤四：技术选型
- 中间件 / 数据库 / 协议

### 步骤五：方案评估
- ATAM 或 SAAM 框架

### 答题模板
```
1. 架构风格选择：【名称】
   - 理由：_______
   - 优点：_______
   - 缺点及优化：_______

2. 质量属性实现：
   - 【属性1】：通过【策略】实现
   - 【属性2】：通过【策略】实现

3. 技术选型：
   - 【中间件/框架】：适用场景
```

## 论文专题：写作框架

### 摘要（300字以内）
```
本文以【项目名称】为例，探讨了【主题】在系统架构设计中的应用。
该项目面临【挑战/问题】。
作者采用了【方案/架构风格】进行设计，
通过【具体措施】解决了关键问题。
最终系统实现了【效果/收益】。
```

### 正文结构
#### 第1段：项目背景
- 项目名称/规模/周期/团队
- 项目目标/主要功能
- 遇到的难点

#### 第2段：方案设计
- 架构需求分析
- 架构风格选择（2-3种候选 + 对比分析）
- 选型理由

#### 第3段：具体实现
- 架构设计图描述
- 关键模块/组件
- 质量属性实现策略（可用性/性能/安全等）

#### 第4段：效果与评价
- 运行效果数据
- 遇到的问题及解决
- 经验总结

#### 结尾段
- 总结全文
- 展望未来

### 评分要点
- 理论基础扎实（引用权威观点）
- 实践结合紧密（真实项目细节）
- 字数 2000-2500 字
- 摘要简洁有力
- 逻辑清晰，层次分明
